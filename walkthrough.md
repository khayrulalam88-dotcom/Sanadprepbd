# Security Summary

Following the final full-stack production readiness review for Sanad Prep BD (React + Vite + TypeScript frontend, Cloudflare Workers + D1 edge API, Express preview parity server, Firebase Authentication, and Cloud Firestore named database), all security controls and newly remediated findings are summarized below:

- **CSV Export Hardening (`src/utils/csvExport.ts`, `src/components/AdminPanel.tsx`)**: Replaced unescaped template interpolation and `encodeURI('data:text/csv...')` links in the admin exam results CSV export with `escapeCsvCell` / `buildExamResultsCsv` and UTF-8 BOM `Blob` URLs. Values starting with spreadsheet formula characters (`=`, `+`, `-`, `@`, `\t`, `\r`, including after leading whitespace) are neutralized with a leading apostrophe, embedded quotes are RFC-4180 doubled, and object URLs are revoked after download.
- **Authoritative Subscription & Package Enforcement (`worker/paymentsAndAdmin.ts`, `server.ts`)**: Verified that `/api/payments/create` and `/api/admin/payments/:id/approve` ignore client-submitted amounts and read authoritative package pricing/validity from Firestore `packages` and `config/examDate`. Updated `/api/admin/users/update` in both the Cloudflare Worker and Express server so manual subscription grants look up live Firestore `packages/{id}` documents before falling back to static catalog defaults.
- **Keyless Cloudflare Worker Architecture (`worker/firebaseAuth.ts`, `worker/firestoreRest.ts`, `worker/d1Store.ts`, `worker/migrations/0003_keyless_edge_collections.sql`)**: Completely removed private-key service-account credentials and RS256 service-account JWT minting. The Worker verifies Firebase ID Tokens using Google public JWKS via Web Crypto, forwards verified user/owner ID tokens to Firestore REST API under strict `firestore.rules`, and persists atomic edge transactions (sessions, rate limits, payment requests, subscriptions, exam attempts/results, leaderboard, and question/key caches) in Cloudflare D1.
- **Auth, Single-Owner Admin & Client State Isolation (`src/context/AppContext.tsx`, `firestore.rules`)**: Verified fail-closed Firestore security rules requiring `request.auth.token.email_verified == true` and strict single-owner admin enforcement (`uid` + verified email `khayrulalam88@gmail.com`), isolated answer keys in `/questionKeys`, and tightened logout / auth sign-out state cleanup in `AppContext.tsx` so cached exam results, in-progress attempts, and answered question ledgers are cleared when a session ends.
- **Edge Compatibility & Secrets Hygiene (`wrangler.production.jsonc`, `.env.example`, `server/services/geminiService.ts`)**: Confirmed zero Node/gRPC/Firebase Admin imports in `worker/`, zero private keys or secrets in client env vars or Wrangler configuration files, and disabled Gemini AI usage returning `GEMINI_DISABLED`.
- **Fail-Closed Exam Grading & Edge Key Preservation (`worker/questionCache.ts`, `worker/examsAndResults.ts`, `server.ts`)**: Removed `DELETE FROM question_keys_cache` from `ensureSanitizedQuestionsSyncedD1` so refreshing sanitized questions never wipes edge answer keys. Eliminated silent `?? 0` answer-key fallbacks in `hydrateQuestionDoc` and Express `POST /api/exams/submit`, returning HTTP `503 QUESTION_KEYS_UNAVAILABLE` whenever authoritative keys are missing.
- **Authoritative Subscription Revocation Sync (`worker/firestoreRest.ts`, `worker/d1Store.ts`)**: Added `firestoreReachable` tracking to `checkUserHasActiveSubscriptionRest` so `checkUserHasActiveSubscriptionKeyless` reconciles stale D1 `edge_subscriptions` rows to `cancelled` and denies access when Firestore authoritatively reports no active subscription, reserving D1 fallback strictly for genuine Firestore outages.
